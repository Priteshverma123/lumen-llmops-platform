# Lumen architecture

Diagrams: [`docs/diagrams/lumen.drawio`](diagrams/lumen.drawio) (10 pages, generated by `build_diagrams.py`).

## 1. Components

| Service | Role | Scales by |
|---|---|---|
| `api` (FastAPI) | OTLP ingest endpoint, query API (traces, sessions, metrics), scores/feedback, prompt registry, experiments, datasets, annotation queues, alert rules | replicas behind a LB (stateless) |
| `ingest` | Redis-stream consumer group: decode → normalise → price → batched ClickHouse insert | consumers in the group |
| `worker` (arq) | online evaluators, alert evaluation, experiment auto-stop, drift, re-embedding jobs, raw-batch retention | replicas (cron jobs are de-duplicated by arq) |
| `embedder` | central embedding service: cache, single-flight, micro-batching, TEI/OpenAI backends | replicas + TEI GPU nodes |
| Postgres | transactional state: projects, keys, prompts, labels, eval runs, experiments, datasets, queues, alert rules, model registry | vertical / managed |
| ClickHouse | telemetry: `spans`, `scores`, `embedding_requests`, `llm_minute`, `llm_hour` | managed / replicated cluster |
| Redis | ingest stream, eval queue, arq jobs, auth & embedding caches, prompt invalidation pub/sub | `noeviction`, AOF |
| MinIO/S3 | raw OTLP batches (durability + replay), re-embedding inputs/outputs | object storage |

## 2. Data flows

**Ingest (durable first).** `POST /v1/traces` (OTLP/HTTP protobuf or JSON, gzip) → auth (project key, `ingest` scope) → size/backlog checks → raw batch to S3 → `XADD lumen:ingest` pointer → `200`. The consumer group reads up to 50 messages, merges them into one insert, and `XACK`s only after ClickHouse accepts. `XAUTOCLAIM` recovers messages from crashed consumers; after 5 deliveries a poison batch moves to `lumen:ingest:dlq` (raw data still in S3). Insert dedup tokens (`non_replicated_deduplication_window`) make retried batches idempotent, so at-least-once delivery has an exactly-once effect.

**Backpressure.** When the stream exceeds 50k pending batches the API returns `429 Retry-After`, which OTLP exporters retry. Overload becomes delay instead of memory growth or data loss.

**Query.** Dashboards and the metrics API read the AggregatingMergeTree rollups (`llm_minute` → `llm_hour`, via chained materialized views). Trace detail reads `spans` by `trace_id` (bloom-filter index) and returns `depth` + `offset_ms` for waterfall rendering.

## 3. ClickHouse schema rationale
* **One wide, insert-only `MergeTree` for spans.** Trace-level attributes (tenant, user, session, prompt version, variant) are denormalised onto every span, so no query joins traces to observations. Langfuse moved away from `ReplacingMergeTree` + `FINAL` and trace↔observation joins after both hit memory limits (blog, Mar 2026).
* `ORDER BY (project_id, toStartOfMinute(start_time), xxHash32(trace_id), span_id)` serves the dominant access pattern (one project, a time range). `SAMPLE BY xxHash32(trace_id)` allows approximate queries on huge ranges. `PARTITION BY toYYYYMM`, with tenants never used as partitions.
* `LowCardinality` on enum-like strings; ZSTD on previews; `Map` for leftover attributes; TTL 90 days (rollups 400 days and 3 years).
* Scores are small and occasionally edited (annotations), so `ReplacingMergeTree(updated_at)` is acceptable there. Reads still use `argMax(..., updated_at)`, never `FINAL`.
* Operational rules: UTC only, TTL on system logs, large batched inserts (avoids "too many parts"), a read-only user for Grafana.

## 4. Semantic-convention mapping
The GenAI conventions moved to `open-telemetry/semantic-conventions-genai` in v1.42 (Jun 2026) and remain at *Development* stability. `telemetry/semconv.py` maps several spellings of each field to one column, in priority order:

| Column | Accepted attributes |
|---|---|
| provider | `gen_ai.provider.name` → `gen_ai.system` → `llm.provider` |
| input/output tokens | `gen_ai.usage.input_tokens`/`output_tokens` → legacy `prompt_tokens`/`completion_tokens` → OpenInference `llm.token_count.*` |
| cache tokens | `gen_ai.usage.cache_read.input_tokens`, `…cache_write…` (+ legacy names) |
| session / user | `gen_ai.conversation.id` / `user.id` |
| prompt | `gen_ai.prompt.name` / `gen_ai.prompt.version` |
| experiment | `lumen.experiment.id` / `lumen.experiment.variant` |

Each row stores `semconv_version`, so a spec change becomes a new mapping version instead of a data migration.

**No double counting.** Per the spec, `input_tokens` *includes* cached tokens, so ingest subtracts cache read/write before pricing. Producers that already report disjoint buckets set `lumen.usage.disjoint=true`.

## 5. Cost
Versioned YAML manifests (`pricing/manifests/*.yaml`, each with `version`, `effective_from` and a sha256 of its models):
* models match by regex, most specific first;
* long-context **tiers**;
* separate cache read/write and optional reasoning prices;
* the manifest is chosen by span time, so historical rows keep the prices of their day;
* cost is computed once at ingest, and a client-supplied cost (`lumen.cost_usd`) wins;
* unknown models cost 0 with `cost_source='unknown'`; prices are never guessed.

## 6. Prompt registry
* Versions are immutable (a DB trigger rejects `UPDATE`). Labels are movable pointers with full `label_history`.
* Templates are sandboxed Jinja2 (`ImmutableSandboxedEnvironment`, `StrictUndefined`), and variables are validated against the version's JSON Schema.
* A cache-friendliness lint warns when a variable precedes more than 200 static characters, because provider prompt caches match prefixes.
* **Promotion gate:** the `production` label moves only to a version with a passing `eval_runs` row. An override requires a reason and is audited. Rollback returns the label to its previous version.
* **SDK:** stale-while-revalidate. Labels stay fresh for 60 s, then refresh in the background with ETag/304. Pinned versions are cached forever. If Lumen is unreachable, a fallback prompt is used, so an observability outage never becomes a product outage. Label changes are published on Redis pub/sub for faster invalidation.

## 7. Experiments
* **Assignment:** `sha256(key:unit) mod 10000`. It is deterministic and salted per experiment, and identical in the SDK (no network) and on the server.
* **Analysis** (`experiments/stats.py`, stdlib only, unit-tested against known values):
  * SRM chi-square at p < 0.001 (a mismatch invalidates the readout);
  * Welch t and two-proportion z for fixed horizons;
  * asymptotic **confidence sequences** (Waudby-Smith et al. 2023, GrowthBook's method) for always-valid peeking;
  * optional CUPED with a pooled θ;
  * guardrails: error-rate Δ, cost ratio, p95 latency ratio.
* **Auto-stop** only on harm, SRM or a guardrail breach; wins go to a human to ship.
* `bench/aa_simulation.py` shows the calibration: peeking a fixed-horizon test inflates false positives, while the confidence sequence stays ≤ α.

## 8. Online evaluation
Deterministic per-trace sampling at ingest feeds a bounded eval queue.
1. **Cheap checks on every sampled span:** PII (regex plus a Luhn check for cards), refusal, JSON validity, truncation.
2. **LLM judge:** a groundedness judge runs only when captured context exists. It calls an OpenAI-compatible endpoint (Atlas gateway, pinned `judge` route) with a strict JSON schema.
3. **Human review:** low scores (< 0.5) go to an annotation queue (`FOR UPDATE SKIP LOCKED` claims, 15-minute locks).
4. **Calibration:** human labels calibrate the judge via Cohen's κ (`evals/calibration.py`).

## 9. Alerting
Detectors are pure functions (`alerts/detectors.py`). The engine runs every minute and notifies only on state transitions.
* **SLO burn rate:** multi-window, multi-burn-rate (1h&5m > 14.4×, 6h&30m > 6×).
* **Cost anomaly:** robust z-score (median/MAD) against the same hour-of-week, with a minimum-dollar floor.
* **Quality drop:** 24h vs 7d.
* **Prompt-cache hit-ratio collapse:** catches unstable prompt prefixes, a silent cost regression.
* **Query drift:** daily embedding-centroid distance.

## 10. Embedding service
* **Cache key** `emb:{model@version}:{input_type}:{sha256(NFC-normalised text)}` with float16 values. The versioned model id makes mixing vectors across model versions impossible.
* **Single-flight:** identical in-flight texts share one future.
* **Micro-batcher:** budget = longest sequence × batch size (TEI's padded accounting), a max-wait window (default 5 ms, halved when queries wait), and query priority over documents. A bounded queue returns 429.
* **Endpoints:** TEI-compatible `/embed` and `/rerank` (Atlas can point at it with no code change), OpenAI-compatible `/v1/embeddings`, and native `/v1/embed` (Matryoshka `dimensions`, `int8`/`binary` output).
* **Re-embedding migrations:** resumable per file, writing JSONL for consumers to build a new index and swap aliases.

## 11. Security
* Project-scoped API keys (`lmn_…`, SHA-256 at rest, 60 s cache, scopes `ingest`/`read`/`write`/`admin`). Bootstrap requires a deployment token; there are no default credentials.
* Content capture is **off by default**. The collector deletes `gen_ai.input/output.messages`. Previews are truncated and stored with ZSTD compression.
* Logs redact keys. Grafana uses a read-only ClickHouse user. All SQL uses bound parameters.
* Infra ports bind to 127.0.0.1. Containers run as non-root. CI pins actions by SHA, scans images with Trivy and produces an SBOM.
